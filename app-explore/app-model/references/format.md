# app-model/1 format

One app's ontology in one YAML file: `app-model.<source>.yaml`, with `<source>` one of `code`, `docs`, `app` or `merged`. The vocabulary is skaileup's (`_concept/glossary.md`, `07_screens`, `05_features`), so a merged model can be proposed into a `_concept/` tree without translation. `schema/app-model.schema.json` is the machine-readable shape (editors pick it up from the file's first line); `model.py validate` checks it plus the references between entries.

```sh
PY="uv run --quiet --with pyyaml==6.0.3 python3"
$PY <app-model dir>/model.py validate app-model.code.yaml   # ok: 12 terms, 9 relations, 14 screens, 4 tasks, 0 features
$PY <app-model dir>/model.py slug "Überweisung"              # ueberweisung
$PY <app-model dir>/model.py json app-model.code.yaml        # the same model as JSON
```

## Top level

| key | value |
|---|---|
| `schema` | always `app-model/1` |
| `source` | `code · docs · app · merged` |
| `app` | `{name, root, url}`: `root` the repo's absolute path or null, `url` the running app or null |
| `provenance` | `{made_by, made_on, source_sha, inputs}`: `made_by` the skill or script, `made_on` `YYYY-MM-DD`, `source_sha` the repo's `git rev-parse HEAD` or `none`, `inputs` the paths, globs or data dir read (a missing file read as `<path> (absent)`) |
| `terms` `relations` `screens` `navigation` `tasks` `featuresets` `features` | lists, below; each is present, empty when the source has none |

Keys within an entry follow the order shown below, `id` first.

## Terms

```yaml
- id: fall                 # skaileup slug of the UI label (model.py slug)
  label: Fall              # the word the users see
  aliases: [Verlauf, case] # other words for the same thing: code names, _Avoid_ words, UI synonyms
  definition: Ein Behandlungs- oder Begutachtungsverlauf einer Patientin.   # or null
  kind: object             # object · role · event · state · value · concept
  class: core              # core · supporting · child · junction · system · null
  axes:                    # only on kind object
    navigation: primary    # primary · contextual · none · null
    lifecycle: owned-by:patient   # independent · owned-by:<term id> · link · null
    origin: user           # user · system · derived · null
    operations: [create, read, edit, delete]   # subset of create · read · edit · delete · archive
  attributes:
    - {name: status, home: fall-detail}   # home: a screen id, none, several, or null when unknown
  evidence:
    - {ref: server/db/schema/faelle.ts:12}
  grade: extracted         # extracted · inferred · needs_review
```

- **kind** as in skaileup `tree/glossary.md` § Format: an object is a noun the user manages, a role a kind of person or actor, an event something that happens and is named aloud, a state a named condition of another term, a value a typed word with no life of its own, a concept any other project word.
- **class** as in `app-patterns.md` P1: core has its own navigation entry and index; supporting is shown inside core objects with its own screens; child lives only inside one parent; junction joins two objects; system is generated by the app.
- **axes** as skaileup's four object axes. A source that cannot tell a value writes null.

## Relations

```yaml
- {subject: patient, predicate: has-many, object: fall, evidence: [{ref: server/db/schema/faelle.ts:20}], grade: extracted}
```

`predicate` is a kebab verb phrase (`has-many`, `belongs-to`, `placed-by`). Both ends are term ids.

## Screens and navigation

```yaml
screens:
  - id: faelle-index       # ^[a-z][a-z0-9-]{1,47}$; app source uses the crawl's state id (s03)
    route: /faelle         # or null
    kind: page             # page · dialog · menu · tab · drawer · popover
    shows:
      - {term: fall, as: row}      # row · card · chip · peek · page (skaileup representations)
    actions:
      - {verb: create, term: fall, target: fall-new}   # term and target may be null
    evidence: [{ref: app/pages/faelle/index.vue:1}]
    grade: extracted
navigation:
  - {from: faelle-index, to: fall-detail, label: Öffnen}
```

## Tasks

```yaml
- id: t1                   # slug
  title: Einen neuen Fall anlegen
  role: member             # a term id of kind role, or null
  verb: create
  term: fall               # or null
  screens: [fall-new]      # where it is done
  evidence: [{ref: walk:t1}]
  grade: inferred
```

## Featuresets and features

```yaml
featuresets:
  - {id: data-and-domain, purpose: A member lists, creates and changes cases.}
features:
  - id: manage-faelle
    featureset: data-and-domain
    outcome: a member creates, finds and edits a Fall
    terms: [fall]
    ops: [{term: fall, op: create}, {term: fall, op: edit}]
    screens: [faelle-index]
    tasks: [t1]
    roles: [member]
    status: built          # built · hidden · unbuilt · undocumented · ui-only · null
    evidence: [{ref: _concept/05_features/featuresets.md:56}]
    grade: extracted
```

Per-source files leave both lists empty, except `docs`, which imports the roster (`import_concept.py`). Only the merged file gets the derived map (`feature-map.md`); `featuremap.py render` sets `status`.

## Evidence

`evidence[].ref` is one of: `path/from/repo/root:line`, `docs/x.md#heading`, `_concept/glossary.md:12`, `state:s03` (an app-explore state), `walk:t2` (an app-explore walk), `persona:p2` (an app-explore persona). `grade` is `extracted` when the value was read verbatim from the cited place, `inferred` when it was concluded, `needs_review` when a human should look.

## Merged files

`compare.py run` writes `app-model.merged.yaml`. On top of the above, every term, relation, screen, task and attribute carries

- `seen_in: [code, docs, app]`: the sources it was found in;
- `ids: {code: …, docs: …, app: …}`: its id in each of them;

and each `axes.operations` entry is written `{op: edit, seen_in: [code]}` instead of the bare op. Per-source files carry neither (`validate` reports both).

## YAML rules

- PyYAML reads YAML 1.1: an unquoted `no`, `yes`, `on`, `off`, `null`, `~`, a date or a number becomes a bool, null, date or number. `validate` reports such a value where text belongs as `<path>: expected string, got bool (quote the value)`. Agents that write a source file quote every such value and run `validate` before they return, fixing each reported line.
- `load` turns unquoted dates into ISO text before validating (as skaileup does for frontmatter dates).
- `save` writes `# yaml-language-server: $schema=<schema path>` as the first line and dumps with `yaml.safe_dump(sort_keys=False, allow_unicode=True, width=120)`, which quotes ambiguous strings (`'no'`, `'2026-11-12'`), so a written file reads back the same in PyYAML and in Bun (`Bun.YAML.parse`).
